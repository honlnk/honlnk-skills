# BOSS 直聘（zhipin.com）Ego 实测经验

实测日期：2026-11-12 初测，2026-11-17 复测（ego-browser 0.6.2.10 / Chromium 156）。只读链路已验证浏览首页、搜索职位、读取列表与 JD 详情；**外发链路已于 2026-11-17 实测**：发起沟通（立即沟通）→ 进入会话 → 发送文字开场白，20 个岗位全部送达，未触发风控。

## 一、登录态与安全边界（先读这节）

- **Ego 里直接是登录态**：首页右上角显示「纪洪申」，消息 / 简历入口齐全。来源是 Chrome profile 导入（`ego-browser import`）。不要把 Ego 当无痕环境。
- **只读任务可以点**：职位标题（仅切换右侧详情，不发起沟通）、城市与筛选条件、翻页。
- **只读任务绝不点**：「立即沟通」（`javascript:;` 锚点，就在右侧详情面板，极易误点）、「收藏」（改变账号状态）、任何分享 / 举报入口。
- **外发动作（立即沟通、聊天、发附件简历）也走 Ego**，由 `boss-zhipin-application` 执行。发起沟通与发送文字消息已于 2026-11-17 实测通过（20/20 送达）；**发送简历附件仍未验证**，只对用户已确认的单个岗位执行。

## 二、URL 与导航模式

| 目的 | URL | 说明 |
|---|---|---|
| 职位搜索（推荐入口） | `https://www.zhipin.com/web/geek/jobs?query=<关键词>&city=<城市码>` | **jobs 带复数 s**；带 query + city 参数直达，免 UI 点选 |
| 首页 | `https://www.zhipin.com/` | 会按 IP 302 到城市首页，本机实测跳 `/chengshi/c101120400/`（德州） |
| 职位详情 | `/job_detail/<加密ID>.html` | 从列表快照取完整链接（带 pk/lid/sessionId 追踪参数，直接用即可） |
| 公司主页 | `/gongsi/<加密ID>.html` | 列表卡片公司名链接 |

- **重定向坑**：旧入口 `/web/geek/job`（单数）会 302 到 `/web/geek/jobs`，直接用单数 URL 首拍快照常为空。构造 URL 时一律用复数。
- **城市码**：101020100 上海、101120400 德州（均为实测）。城市码也可从页面城市链接（如 `/c101020100/`）反查。
- 首页默认城市按 IP 定位（本机为德州），与用户求职目标无关；搜索任务必须显式带 city 参数或在页面切城市，并核对结果地点。

## 三、jobs 搜索页结构（快照要点）

布局：顶部导航 + 期望 tab（推荐 / 已有期望 / 添加求职期望）→ 搜索框与筛选栏 → **左侧职位列表 + 右侧 JD 详情面板**。

- 搜索框：`input[placeholder="搜索职位、公司"]`（首页则是 `input[name="query"]`）。
- 职位卡片：标题是 `href` 含 `/job_detail/` 的链接；同卡片带公司（`/gongsi/` 链接）、地点、经验、学历。
- **右侧详情面板默认选中第一个职位**，含职位名、薪资、地区、经验学历、「收藏」「立即沟通」、完整「职位描述」、**招聘者姓名与在线状态**以及工作地址——**读 JD 不需要进入独立详情页**，点击左侧职位标题即可切换右侧详情。
- **快照文本不可信，完整 JD 用 `document.body.innerText`**：快照里的职位描述会被截断且碎片化（`...`、断行错乱），body innerText 则完整连贯（2026-11-17 实测字节跳动岗可拿到团队介绍/职责/要求/加分项全文）。快照只用来定位和核对字段。
- 筛选栏为文字项（工作区域 / 职位类型 / 求职类型 / 薪资待遇 / 工作经验 / 学历要求 / 公司行业 / 公司规模 / 融资阶段 / 清空），快照可直接按 text 定位。

### 三.1 发起沟通与发送开场白（2026-11-17 实测）

- 职位详情页的 `a.btn-startchat` 有两个（一个可见、一个隐藏），用 `css=.btn-startchat >> nth=0` 定位可见项；文案可能是「立即沟通」或「继续沟通」。
- 点击「立即沟通」后**当前页直接跳到 `/web/geek/chat`** 并选中该招聘者会话，不自动替用户发消息。点击后 `redirect-url` 可能短暂缺失（元素重渲染）；需要会话链接就重新进 job_detail 再读。
- 会话输入框：`#chat-input`（`contenteditable="true"`），发送按钮：`button.btn-send`（空内容时带 `disabled`）。`fill()` 不适用，用 `click("#chat-input")` + `keyboard.paste({ text })`。
- 发送前用 `.chat-conversation` 头部核对招聘者 / 公司 / 职位；发送成功证据：输入框清空、会话末尾出现该消息、左侧 `.user-list` 该条显示「[送达]」。
- 连续发送 20 个岗位（间隔约 4.5 秒）未触发验证码或限流；「已读」状态在列表里直接可见。
- **每日沟通额度弹窗（2026-11-17 实测）**：当日沟通量到 120 位时，点「立即沟通」会弹出 `.dialog-wrap.greet-pop`「您今天已与120位BOSS沟通，还剩30次沟通机会哦」。弹窗的 `.dialog-layer` 会拦截对 `a.btn-startchat` 的指针事件，表现为 `page.click` 报 `div intercepts pointer events`、或点击后仍停在 job_detail。处理：点弹窗内文本为「好」的按钮，页面随后自动进入 `/web/geek/chat` 并出现 `#chat-input`；无需再点一次「立即沟通」。当日上限约 150 位。
- **从聊天列表打开指定会话**：`page.click('css=.user-list li >> nth=N')` 可以打开；在 `page.evaluate` 里对 `li` 调 `element.click()` 不触发跳转（Vue 监听不在 li 本身）。列表首屏约 46 条、渲染需 5 秒左右，更早的会话不会随滚动加载；因此超过 46 条的旧会话无法在列表里逐条回看。
- 会话已建立但未发消息时，列表末条显示「您正在与Boss×××沟通」，可据此判断是「只建了会话」而非「已发招呼」。
- **核验 46 条以前的旧会话**：从 job_detail 点「继续沟通」后，页面会先显示空态「与您进行过沟通的 Boss 都会在左侧列表中显示」，约 7–10 秒后才挂载 `#chat-input` 与 `.chat-conversation`。等挂载后读会话末尾，即可确认当初的开场白是否真的送达；不要在 2–3 秒的空态阶段判定「会话不存在」。

## 四、已知坑

1. **薪资反爬字体**：jobs 列表页与详情面板的薪资数字在文本层缺失（读到 `"-元/天"`、`"K·薪"`），**首页**推荐位薪资反而正常（如 `20-40K`、`15-25K·13薪`）。需要精确薪资时：读详情面板其余字段 + 必要时截图目视核对，不要把缺数字的薪资当真值输出给用户。
2. **首拍空快照 / canvas 骨架**：列表渲染前先出现 canvas 骨架，此时 `body.innerText` 已有 578 字符（导航文字），按长度判断会误判就绪。正确判据：`document.querySelectorAll('a[href*="/job_detail/"]').length >= 3`（2026-11-17 复测，就绪后等待仅 6ms）。
3. **分页 / 滚动**：列表超出视口时快照尾部会提示 `[more content below the viewport]`，用 `full_page` 快照或滚动，不要断言"没有更多职位"。
4. 大批量抓取（多关键词 × 多页）用 Ego 批量流程（见第六节），控制频率与页数，遇到风控立即停止。
5. **搜索词归一化**：`AI Agent`（空格）与 `AI-Agent`（连字符）返回结果完全一致，无需纠结分隔符。

## 五、与其它工具的衔接

- 产出核对卡 / 筛选短名单：Ego 读 JD → 按项目 `boss-zhipin-application` 的核对卡格式整理 → 用户确认后由该 skill 在 Ego 中发起沟通。
- 薪资数字缺失：暂无独立抓取器可补，需要精确薪资时用截图目视核对；不建议为此引入其它工具。

## 六、批量抓取方案（Ego 版，待验证）

独立抓取器（boss-zhipin-scraper）已于 2026-11-17 废弃，批量调研改用 Ego。以下流程尚未大规模实测，按保守参数起步：

1. 用 URL 模板逐组（关键词 × 城市）导航：`/web/geek/jobs?query=<kw>&city=<code>`；每组等待 `a[href*="/job_detail/"]` ≥ 3。
2. 用一次 `page.evaluate()` 提取卡片结构化字段（标题/链接/公司/地点/经验学历/标签），按 href 去重。注意页脚也会出现 `/job_detail/` 链接（"职位搜索"），需过滤。
3. 翻页：优先点击"下一页"按钮而非猜 URL；每页提取后检查是否出现验证码、登录失效或空列表。
4. 频率控制：页间等待 3–5 秒；单次任务建议 ≤ 5 页 / ≤ 3 个关键词；出现验证码、登录失效或连续空列表立即停止，不绕过。
5. 结果写入项目 `调研/` 目录的 JSON/Markdown，文件名带日期；跨任务不要复用同一个 taskSpace。
6. 实测后把真实耗时、页数上限与风控触发条件回写到本节。
