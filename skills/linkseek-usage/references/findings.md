## 基线数据（2026-09-28，来自历史使用记录分析）

技能创建时的已知事实，供未来实验对照：

- `web_search` 空结果率约 21%（543 次调用中 121 次空）；按月趋势 7 月 16% → 8 月 29% → 9 月 24%
- 显式传 `language=zh-CN` 空率 32%，`language=en` 为 8%，不传约 23% → 已据此在技能中规定默认不传
- 空结果后同 query 原样重发 100% 仍空；改写 query 措辞约 50% 可救回
- 抓取类工具（web_fetch / web_fetch_render）失败率 <1%，非常稳定
- searx.space 公开实例实测（2026-09）：bing 错误率 0%、google 17%、ddg 61%、brave 73%、startpage/qwant 81-95%、baidu 98.5%（海外出口视角）——降级重试链选 bing,google 作为最后一档即依据于此
- 服务端 2026-09-28 起新增：空结果自动降级重试 + 诊断回传（部署前旧格式无诊断）
- 服务端 2026-09-29 起新增：异步任务系统——四个慢工具 `defer=true` 脱手、纯异步 `web_research`（fast/standard/deep 三档）、`get_result` 共用取结果（结果保留 60 分钟，重启丢失）；全链路移除 LLM 输出 token 上限（原全局 2000 截断），LLM 超时放宽为 10 分钟总闸。**注意：部署前的服务端没有这些参数/工具**

## 2026-10-26 SearXNG 中文短查询返回"非空但完全跑偏"的结果，切 cloud 直接提质
- 状态：候选
- 场景：查国产手机型号（"V2361A 参数"、"vivo S20 型号 V2361"），general 分类
- 标准方法：`web_search`（auto/SearXNG）→ 结果：非空但 100% 不相关（DeepSeek 官网、豆包新闻等无关域名），两次复现；这类"质量型失败"不触发空结果诊断，容易被误当成"网上没这信息"
- 新方法：`web_search provider='cloud'`（英文技术查询）→ 结果：10 条全部切题（Google 官方文档 + GitHub issue 原文）
- 结论：SearXNG 对部分中文短查询存在"有结果但不相关"的质量型失败，符合第六节场景 2 的切 cloud 时机。注意两次对比的查询语言不同（中/英），未做同语言严格对照；后续如再复现可升级「已确认」
