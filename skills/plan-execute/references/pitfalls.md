# 模型默认行为对策表（活文件）

每踩一个新坑追加一行：坑的描述 + 可直接抄进计划 / 提示词的约束句。这张表是本技能沉淀经验的地方——它不追求一次写全，追求每次踩坑后变厚一点。

| # | 坑（模型默认行为） | 对策（约束句） |
| --- | --- | --- |
| 1 | 开放选择题选省事项，后果用户承担 | 计划中影响用户体验的取舍必须拍死；禁止把「任选其一」留给施工方 |
| 2 | 默认值 / 格式变更不做存量迁移，升级收益对旧数据为零 | 提示词固定检查项：「本改动有无旧数据 / 旧配置要迁移？」 |
| 3 | 验证不了时悄悄降级或跳过，且不主动说 | 提示词固定要求：交付必附「未验证清单」——降级验证明示兜底方式和用户复核点 |
| 4 | 合规取舍被当成「不用报」（有文档依据就不提） | 汇报固定节：「留下的尾巴」——每条取舍翻译用户影响，合规的也报 |
| 5 | 上下文压缩后拿陈旧文件记忆做判断 | 工作规则：涉及具体文件的关键判断，写之前重读文件，不信记忆 |
| 6 | 时序修复无测试，竞态类 bug 复发 | 规则：时序 / 竞态类修复必须带事件序测试（乱序事件序列断言） |
| 7 | 提交规范凭惯例写，被 commitlint 打回返工 | 提示词写明：先读仓库提交规范确认合法前缀与 scope，再提交 |
| 8 | 验收环境知识每轮重新摸索（端口、mock、自动化限制） | 查到的环境知识当场记入项目文档，下轮提示词直接引用 |
| 9 | 新旧机制并存，双倍噪音（只加新的不删旧的） | 计划检查单：替代表写明旧机制删 / 换 / 留 |
| 10 | 顺手实现计划外功能，范围蔓延 | 计划必有「明确不做清单」；施工中发现顺手能改的问题记入日志，不随手改 |
| 11 | 高风险编辑方式（脚本拼字符串替换）埋下静默破坏 | 提示词约束：优先结构化编辑；批量替换后必须全量门禁兜底 |

## 追加新坑的格式

```
| N | 一句话描述坑（什么默认行为、造成了什么后果） | 一句话约束（可直接抄进计划/提示词，写给模型看的） |
```

写完顺手检查：这个坑是对策表已有条的变体吗？是就强化措辞，不是才新增——表太长会被稀释，保持每条都有血案。
